## Defect Register

### `D-1` — `IMAGE_SMOKE_IMPORTS` and `PROVIDER_REQUIREMENTS["vertex"]` smoke-test retired `vertexai` instead of `google.genai`

- **Lane:** Production image smoke (`Makefile:117`, `tests/constants/deploy.py:94-102`).
- **Symptom:** After `PR #135` migrated `src/mangomas/adapters/_genai.py`, `adapters/llm/vertex/_sdk.py`, `adapters/llm/vertex/_client.py`, and `adapters/embeddings/vertex.py` to `google.genai`, `make docker-smoke` still runs `import vertexai, ...` inside `mangomas:ci`. A container image missing `google.genai` (or broken on import) passes `make docker-smoke` silently while failing every Vertex request at runtime.
- **Root cause:** `tests/constants/deploy.py:98-101` and `Makefile:117` kept `smoke_module="vertexai"` from the pre-`PR #135` SDK.
- **Fix:** Update `PROVIDER_REQUIREMENTS["vertex"].smoke_module` in `tests/constants/deploy.py` and `IMAGE_SMOKE_IMPORTS` in `Makefile` from `vertexai` to `google.genai` (preserving non-protected scope; `test_manifest_provider_contract.py` enforces parity between both).
- **Guard:** `tests/regression/test_aqa_20261115_defects.py::test_d1_vertex_smoke_import_matches_google_genai_runtime`.

### `D-2` — `/readyz` / `check_ready` ignores `MANGOMAS_API__READY_TIMEOUT_SECONDS` and blocks on hanging LLM or DB probes

- **Lane:** Live no-mock TCP `uvicorn` probe (`readyz_honours_ready_timeout_seconds`).
- **Symptom:** Starting `uvicorn` with `MANGOMAS_API__READY_TIMEOUT_SECONDS=1.0` and `MANGOMAS_LLM__TIMEOUT_SECONDS=10.0` against an HTTP endpoint that stalls `8.0s` causes `GET /readyz` to hang for **`8.24s`** instead of failing ready in ~`1.0s`. An unauthenticated readiness probe can therefore pin workers and miss Kubernetes/Cloud Run liveness/readiness deadlines whenever either the LLM backend or database hangs.
- **Root cause:** `check_ready(orchestrator)` (`src/mangomas/api/health.py:86`) awaits `ctx.llm.ping()` and `ctx.repo.list_turns(limit=1)` directly with no `asyncio.wait_for` bound; `create_app()` (`src/mangomas/api/app.py`) reads `api_cfg = get_settings().api` without storing `ready_timeout_seconds` on `app.state`; and `routes/system.py::readyz` calls `check_ready(orch)` with no budget.
- **Fix:**
  - Extract a single shared `_run_bounded_probe(...)` helper in `src/mangomas/api/health.py` supporting an optional keyword `timeout_seconds: float | None = None` on `check_ready(orchestrator, *, timeout_seconds: float | None = None)` (backwards compatible when omitted), bounding both the LLM `ping()` and DB `list_turns(limit=1)` calls via `asyncio.wait_for` when configured and translating `TimeoutError` into `CheckResult(..., status="error", detail=f"timed out after {timeout_seconds:g}s")` + structured warning logs preserving `"LLM ping failed"` / `"DB probe failed"`.
  - Store `app.state.ready_timeout_seconds = api_cfg.ready_timeout_seconds` in `create_app` (`src/mangomas/api/app.py`) and forward `timeout_seconds=getattr(request.app.state, "ready_timeout_seconds", None)` in `routes/system.py::readyz`.
  - Add `ping_delay_seconds: float = 0.0` (`FakeLLM`) and `list_turns_delay_seconds: float = 0.0` (`FakeRepository`) in `tests/fakes.py` for deterministic hermetic guards without sockets.
- **Guard:** `tests/regression/test_aqa_20261115_defects.py::test_d2_*` + `scripts/guard_probe_manifest.json` (`MUT-AQA-1115-01`, `MUT-AQA-1115-02`).

### `D-3` — `MANGOMAS_EVAL__OUTPUT_DIR` (`EvalSettings.output_dir`) is dead config for `json_file` and `sqlite_results` sinks in `mangomas eval`

- **Lane:** Live `mangomas eval` CLI sweep (`live_eval_pass_pow_2_and_sinks`).
- **Symptom:** Running `mangomas eval` with `MANGOMAS_EVAL__OUTPUT_DIR=<dir>` and `MANGOMAS_EVAL__SINKS='["console","json_file","sqlite_results"]'` (as documented in `AGENTS.md` and `docs/eval/harness.md`) exits `2` (`EXIT_CONFIG_ERROR`) with `Eval configuration error: json_file sink requires a string 'path' option`.
- **Root cause:** `EvalSettings.output_dir` (`src/mangomas/config/evaluation.py:184`, `DEFAULT_EVAL_OUTPUT_DIR = "eval-output"`) is never passed into `_build_sinks` (`src/mangomas/cli/commands/_eval_config.py:32-56`) by `src/mangomas/cli/commands/eval.py:223`.
- **Fix:** Extend `_build_sinks(..., *, output_dir: str | None = None)` with backwards-compatible keyword default `None` (leaving direct 3-arg unit callers unchanged), pass `output_dir=cfg.output_dir` from `eval.py`, and when `output_dir` is non-empty and an artifact sink option (`"path"` for `"json_file"` when `--output-json` is absent, or `"db_path"` for `"sqlite_results"`) is absent or `None`, default it via a shared sink-filename mapping to `str(Path(output_dir) / filename)` (`report.json` / `results.db`). Explicitly invalid values (e.g., `""`, non-string) remain rejected with `ConfigError` (`EXIT_CONFIG_ERROR`), and `sink_registry` factories keep their direct `require_str` contract.
- **Guard:** `tests/regression/test_aqa_20261115_defects.py::test_d3_*` + `scripts/guard_probe_manifest.json` (`MUT-AQA-1115-03`).

### `D-5` — Missing finite/boolean/NumPy scalar validation on readiness timeouts & CLI eval gating thresholds, plus duplicated sink constants

- **Lane:** Main-parity SQE/architect audit (`src/mangomas/config/api.py`, `src/mangomas/api/health.py`, `src/mangomas/eval/sink.py`, `src/mangomas/cli/commands/_eval_config.py`).
- **Symptom:** `APISettings.ready_timeout_seconds` lacked `Field(..., gt=0.0, allow_inf_nan=False)`, allowing `<= 0`, `NaN`, or `inf` at Settings parse; `check_ready(..., timeout_seconds=...)` forwarded unvalidated timeouts straight to `asyncio.wait_for` and lacked structured `readiness_probe_*` / `readiness_report` event fields; `_resolve_gating` checked `not 0.0 <= val <= 1.0` directly without `finite_number` (`bool`/`NaN`/NumPy safety); and CLI `_build_sinks` duplicated sink option/filename literals instead of reading shared constants from `mangomas.eval.sink`.
- **Fix:** Constrain `APISettings.ready_timeout_seconds` with `Field(..., gt=0.0, allow_inf_nan=False)`; extract `_normalize_ready_timeout` using `mangomas.utils.json_path.finite_number` and add structured readiness log extras in `api/health.py`; extract `DEFAULT_SINK_ARTIFACTS` and sink name/option constants into `mangomas.eval.sink` (`re-exported` by `mangomas.eval` and consumed by `json_file.py`, `sqlite_results.py`, and `_eval_config.py`); and unify `_resolve_gating` threshold normalization through `finite_number`.
- **Guard:** `tests/regression/test_aqa_20261115_defects.py::test_d5_*` + `scripts/guard_probe_manifest.json` (`MUT-AQA-1115-04`).
