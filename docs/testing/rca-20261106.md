## Register

### D-1 — `SQLiteRepository.__init__` lets `ValueError` from `path_from_sqlite_url` escape untranslated, crashing the CLI with a traceback (exit 1 instead of 2)

- **Lane:** No-mock E2E (`cli_sqlite: MANGOMAS_DB__URL=sqlite:/// exits 2 without traceback`).
- **Symptom:** Running `MANGOMAS_DB__URL=sqlite:/// mangomas chat "hi"` (or any other CLI command that builds an orchestrator) exits `1` with an unhandled `ValueError: Empty sqlite URL path: 'sqlite:///'` traceback on stderr instead of printing `Configuration error: ...` and exiting `2` (`EXIT_CONFIG_ERROR`).
- **Root cause:** PR #115 changed `path_from_sqlite_url("sqlite:///")` in `src/mangomas/adapters/storage/_url.py` to raise `ValueError("Empty sqlite URL path: 'sqlite:///'")` instead of returning `""` (which caused `sqlite3.connect("")` to silently open a temporary database). However, `SQLiteRepository.__init__` (`src/mangomas/adapters/storage/sqlite.py:58`) calls `_path_from_url(url)` without catching `ValueError` and translating it into `ConfigError`. Because `build_or_exit` in `src/mangomas/cli/_runtime.py:82` catches only `MangomasError` and `ImportError`, any `ValueError` from `path_from_sqlite_url` (`sqlite:///`, `sqlite://`, or a malformed IPv6 netloc like `sqlite://[::1`) escapes as an unhandled crash.
- **Fix:** Catch `ValueError` around `_path_from_url(url)` in `SQLiteRepository.__init__` and raise `ConfigError("Invalid SQLite database URL", detail=truncated_exc_detail(exc)) from exc`.
- **Class:** D-n (`src/mangomas/adapters/storage/sqlite.py`).

### D-2 — `SqliteResultsSink.__init__` lets `ValueError` from `path_from_sqlite_url` escape untranslated, breaking `_build_sinks` and crashing `mangomas eval` (exit 1 instead of 2)

- **Lane:** No-mock E2E (`cli_eval: sqlite_results db_path=sqlite:/// exits 2 without traceback`).
- **Symptom:** Running `mangomas eval` with `MANGOMAS_EVAL__SINK_OPTIONS='{"sqlite_results": {"db_path": "sqlite:///"}}'` exits `1` with an unhandled `ValueError` traceback instead of printing `Eval configuration error: ...` and exiting `2` (`EXIT_CONFIG_ERROR`).
- **Root cause:** `_build_sinks` (`src/mangomas/cli/commands/_eval_config.py:42-43`) documents `Raises MangomasError (→ exit 2) on an unknown sink or a misconfigured option`, and `_run_eval_pipeline` (`src/mangomas/cli/commands/eval.py:198`) wraps `_build_sinks` in `try ... except MangomasError:`. `SqliteResultsSink.__init__` (`src/mangomas/eval/sinks/sqlite_results.py:77`) calls `path_from_sqlite_url(db_path)` directly at sink-construction time without translating `ValueError` into `ConfigError` (`SqliteResultsSink._write` caught `ValueError` at emit time, which is too late because URL normalisation happens in `__init__`).
- **Fix:** Catch `ValueError` around `path_from_sqlite_url(db_path)` in `SqliteResultsSink.__init__` and raise `ConfigError("sqlite_results sink option 'db_path' is not a valid SQLite URL or path", detail=truncated_exc_detail(exc)) from exc`.
- **Class:** D-n (`src/mangomas/eval/sinks/sqlite_results.py`).

### ENV-1 — Local TLS inspection filter driver intercepts Python/Node outbound HTTPS without OS truststore

- **Lane:** Pre-flight (`gcloud auth application-default print-access-token`, `pip`, `user-context7` MCP).
- **Symptom:** `SSLCertVerificationError(1, '[SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed: unable to get local issuer certificate')` when `gcloud` or `pip` connects to `oauth2.googleapis.com` / `pypi.org` without `--use-feature=truststore`, and `TypeError: fetch failed` in Node MCP clients (`SSLKEYLOGFILE=\\.\nllMonFltProxy\...`).
- **Class:** ENV. Closed by `scripts/bootstrap_gpu_env.py` (`make venv-gpu`) and [`docs/tooling/env1-tls-inspection-runbook.md`](../tooling/env1-tls-inspection-runbook.md), which export the Windows `ROOT` and `CA` stores to `%LOCALAPPDATA%\mangomas\ca-bundle.pem`, wire `SSL_CERT_FILE`, `REQUESTS_CA_BUNDLE`, `PIP_CERT`, `PIP_USE_FEATURE=truststore`, `NODE_EXTRA_CA_CERTS`, and `CLOUDSDK_CORE_CUSTOM_CA_CERTS_FILE`, and install `torch==2.14.1+cu130` last into `.venv-gpu`. Vertex and GCP Secret Manager live suites remain `NOT-RUN(CREDS)` when `VERTEX_PROJECT_ID` is unset.
